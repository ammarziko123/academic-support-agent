
# Student Frequently Asked Questions

Document ID: DOC-004
Last Updated: 2026-10-01
Data Status: SAMPLE ACADEMY DATA — NOT OFFICIAL

## 1. Accessing the Learning Platform

Students should access course materials through the learning platform provided by the sample academy.

If a student cannot log in, they should:
1. Verify that they are using the correct registered email address.
2. Check that the keyboard language and password entry are correct.
3. Use the password-reset option if available.
4. Try opening the platform in an updated browser.
5. Contact technical support if the issue continues.

Students should never share their passwords or authentication codes with another person.

## 2. Password Reset

If a student forgets their password, they should use the platform's password-reset process.

If the reset email does not arrive, they should check their spam or junk folder and verify the registered email address.

If these steps do not resolve the issue, the student should contact technical support.

Support staff should never ask students to disclose their existing passwords.

## 3. Accessing Session Recordings

Session recordings may be made available when the instructor or course arrangement provides them.

Students should check the course page for a recording link and any availability notes.

If a recording link is unavailable, the student should verify that they are logged into the correct account and enrolled in the relevant course.

Not every session is guaranteed to have a recording.

If a provided recording cannot be opened, the student should contact technical support with:
- Course name
- Session date
- Recording link or page location
- Error message, if available

Students should not share private course links publicly.

## 4. Reporting Technical Issues

Students can report technical issues through the academy's designated support process.

A useful issue report includes:
- Issue category
- Short description of the problem
- Course or platform page affected
- Steps that caused the problem
- Error message, if available
- Priority based on the issue's impact

Students should not include passwords, authentication codes, or unnecessary sensitive personal information.

Examples of issue categories include:
- Login and account access
- Recording and video playback
- Assignment submission
- Course material access
- Other technical issues

## 5. Support Priority Guidance

For the sample academy, students may use these priority descriptions when reporting a problem.

Low: A minor issue with a simple workaround that does not prevent normal learning.

Medium: An issue that disrupts part of the learning process but allows some activities to continue.

High: An issue that prevents an important learning activity, such as submitting an assignment near its deadline, and has no practical workaround.

Priority labels help the support team organize requests. They do not guarantee a particular response time.

## 6. Course Information

Students should consult the course catalog for course topics, prerequisites, expected outcomes, and duration.

If a course-specific detail is missing from the catalog, students should ask the academy for clarification instead of relying on assumptions.

## 7. Assignment Questions

Students should check the assignment instructions and assignment policy before submitting work.

For a missing deadline, they should consult the academic calendar or contact the course instructor.

The support team should not guess a deadline that is absent from the available records.

## 8. Grades and Results

Students should use the grading rubric or officially supplied score weights to understand their results.

A weighted grade can be calculated only when the necessary scores and weights are known.

If score weights are missing, students should ask the instructor or consult the relevant course assessment document.

The assistant must not invent missing scores or grading weights.

## 9. Privacy and Account Security

Students should not send passwords, authentication codes, or payment credentials through support tickets.

Support requests should contain only the information needed to investigate the reported issue.

Requests for private staff information must be referred to an authorized official channel if one exists.

## 10. Frequently Asked Questions

### Can I request a support ticket?

Yes. A student can ask the support system to create a ticket by providing an issue category and a description. A priority may also be supplied.

### Is a ticket created when I describe a problem to the assistant?

Not automatically. A ticket is created only when the student requests ticket creation and the ticket-writing operation succeeds.

### Can the assistant confirm that my problem has been fixed?

Only if reliable system information supports that conclusion. Creating a ticket does not mean the technical problem has been resolved.

### What if my question is not covered by these documents?

The assistant should state that the available knowledge base does not contain enough information and suggest contacting the academy through an authorized support channel.
